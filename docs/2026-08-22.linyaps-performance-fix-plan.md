## Phase A — 专用约束 SKILL（B 方案 + agent 调用优化）

### A1 新建 `skills/src2linyaps.constraints/SKILL.md`

```yaml
---
name: src2linyaps.constraints
description: 【debian-rules-to-linyaps】通用构建约束的唯一权威。承载本 workflow 全部 skills 共享的构建/校验约束，由 agent 在初始化阶段一次性载入，各子 skill 引用本 SKILL 而非各自复述。
user-invocable: false
---
```

内容要点（精炼，非散文）：
- **安装目录**：所有工具（cmake/meson/make/autotools）安装目录用 `${PREFIX}`；禁硬编码 `/usr`/`/usr/local`；bin → `${PREFIX}/bin`、lib → `${PREFIX}/lib`。
- **DESTDIR 黑名单**：仅 `make` 允许 `DESTDIR=`；cmake/meson/autotools/unknown 禁用（防 `${PREFIX}${PREFIX}` 嵌套）。
- **多包合并**：所有 `Package:` 条目并集去重，不区分主包/common-data。
- **运行时依赖存在性核验**：写入 `depends` 前逐包 `apt-cache show` 核验，剔除不存在于 apt 仓库者（Issue 55）。
- **校验契约**：生成的 `linglong.yaml` 必须通过 `validate-linglong-yaml.py --schema linglong-schema.yaml --build-tool <tool>`；`linglong-defaults.json` 为默认值权威。

### A2 agent 侧调用优化（关键：高效启用）

1. 在 agent 的 **Phase 1 初始化**末尾增加：
   ```yaml
   skill({ name: "src2linyaps.constraints" })   # 一次性载入约束契约
   ```
   并在会话状态/todo 记录「约束已加载」，正文明确「后续步骤引用本 SKILL 约束，不重复展开」。
2. 各 `src2linyaps.*` SKILL 的整段约束叙述 → 一行引用：
   ```
   > 遵循 src2linyaps.constraints：${PREFIX} 安装目录、DESTDIR 黑名单、多包合并、运行时依赖存在性核验、校验契约（详见该 SKILL）。
   ```

**落地文件**：
- 新建 `skills/src2linyaps.constraints/SKILL.md`
- 修改 `agents/debian-rules-to-linyaps.agent.md`、`for-multica/agent.md`（加入载入步骤 + 约束引用）
- 精简 `skills/src2linyaps.debian.analyze-control/SKILL.md`、`analyze-rules/SKILL.md`、`build-res-generate/SKILL.md`、`source.analyze-args/SKILL.md`、`src2linyaps.debug/SKILL.md` 的重复约束段

> ⚠️ 权衡：multica 复制模型下 `src2linyaps.constraints` 独立下发，其他 skill 通过 `skill()` 按 name 运行时引用（非跨目录文件 import）。若某环境未下发该 skill，agent 需最小内联 fallback（执行时确认）。

## Phase B — 消除校验回环

### B1 `generate-linglong-yaml.py` 增加版本归一化

在 `skills/src2linyaps.debian.build-res-generate/scripts/generate-linglong-yaml.py`：

1. 新增 `normalize_version()`：
   - 输入任意 Debian 版本（如 `30.2.3+dfsg-3deepin1`、`1:2.3~rc`、`4:25.04.3-2deepin1`）；
   - 提取前 4 个纯数字段 → `MAJOR.MINOR.PATCH.REV`，缺失补 `0`，忽略非数字尾部（`+dfsg`、`~rc`、epoch `1:` 前缀等）；
   - 示例：`30.2.3+dfsg-3deepin1` → `30.2.3.0`。
2. 在 `version = get_value(args.package_version, ...)`（:379）后应用 `normalize_version()`；
3. `build_yaml()`（:202）使用归一化后的 `version` 写入顶级 `version` 与 `package.version`。

### B2 校验脚本报错输出可执行修复命令

# 增补方案：`src2linyaps.constraints` 引用歧义收敛（中庸版）

> 日期：2026-08-23
> 动机：A 阶段落地后复核发现，子技能以**裸名**「遵循 `src2linyaps.constraints`（…）」引用约束，而该名与其他技能**文件夹**同名前缀（`src2linyaps.*`）。在孤立上下文（子 agent / 独立 `debug` 入口）读取时，模型无法判定它是**可加载 SKILL** 还是**文件夹**。
> 目标：在不增加 token 的前提下消除歧义、提升命中率。

## 核心原则

- 「如何加载 / fallback」的文字**只存在于两个父 agent 与 `src2linyaps.constraints` SKILL 自身**，子技能不复述加载方式。
- 子技能中**纯冗余**的「遵循 `src2linyaps.constraints`（…）」复述**直接删除**（其内容实为父 agent 已于 Phase 1.3 一次性载入，或本技能自身 description/脚本行为）。
- 确需保留的**跨技能含义**行，将裸名统一改写为「`src2linyaps.constraints` **SKILL**」自标识（比裸名仅 +1~2 token，非完整限定语）。
